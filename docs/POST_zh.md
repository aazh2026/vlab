# 我写了个资产配置回测框架，然后发现它骗了我

> 这是一篇可以改写后发布到 V2EX / 掘金 / 知乎 / 即刻 的文章草稿。
> 配合仓库 https://github.com/aazh2026/vlab 食用。

## 起因

我想知道自己现在这套资产配置到底行不行。

货币 15% + 国债 20% + 红利低波 25% + 沪深300 15% + 黄金 10% + 美股金融 5% + 纳指 5% + 美元 5%。

听起来很稳，对吧？债券打底、红利吃息、宽基跟涨、黄金对冲、美元锁汇。

所以我写了个回测脚本，跑了一遍，看着那条漂亮的净值曲线，给自己的结论是：

> **年化 6.78%，最大回撤 -13%。**

这句话我差点就拿去做真实的投资决策了。

## 然后我意识到：我不知道这个数字是不是真的

不是"我不确定"，是"我根本无从知道"。

那个脚本是我十分钟写的，行情数据是爬来的，跨市场对齐没做，货币基金的处理我没想过，权重归一化我随手写了行 `sum(w)/sum(w)`。

**问题在于：错掉的回测不会报错。** 它只会给你一条平滑的曲线，让你以为一切都好。

所以我决定把它做成一个正经的系统。真实行情源、跨市场对齐、交易成本、双窗口、指标校验。然后写回归测试。

## 测试立刻抓出了四个 bug

### Bug 1：跨市场休市日没对齐

A股和美股休市日不一样。我按各自日期取值再合并，结果美股休市那天，A股持仓的价格还在，但美股持仓被记成了 0。

回撤直接算出 **-90%**，波动 **1618%**。

修法：forward-fill，休市日沿用上一个有效价格。

### Bug 2：货币 ETF 的收益蒸发了

我配置里 15% 是货币基金（511990）。跑完发现，"全部持有货币基金"的年化是 **0%**。

不对吧？

后来查到：交易型货币基金的**净值恒定 100**，收益是以**份额**形式派发的。你从价格数据里根本看不到它涨过。

真实水平是 1.67%。这个 bug 会让所有现金层的收益凭空消失。

修法：按 1.8% 年化合成一条累积曲线。

### Bug 3：这个最要命 —— 权重过度归一化

我原来写的是：把权重归一到 1。

问题在于，早期有些 ETF 还没上市、拿不到价格。归一化的时候，分母只算了"能买的那些"，于是**买不了的那个资产的权重，被摊到了其他资产头上**。

结果：2008 年凭空出现单年 **-30%** 的跌幅。

那不是我的策略亏的，那是我的代码编的。

修法：不归一化。买不了的资产，权重就留在现金里。

### Bug 4：窗口偏差 —— 代码全对，结论全错

这条最阴险，因为它不是代码 bug。

美股数据有 2001 年起的全历史，但 A 股 ETF 大多是 2012 年后才上市的。我从 2001 年开始回测，**等于让后来才存在的资产提前入场**。

这不叫穿越周期，这叫穿越时空。

修法：强制分成两个窗口，结论分开陈述：

- **窗口 A｜投资现实口径（2019-01-18 ~ 至今）** — 起点是所有标的都已上市的最早交易日。现实中能执行的口径。
- **窗口 B｜指数代理长口径（2008-07 ~ 至今）** — 用中证红利等**指数**代理早期还不存在的 ETF，覆盖 2008 危机。

## 修复前后

同一套配置，同一个 2019–2026 窗口：

| | 我最初报的 | 修复后 |
|---|---|---|
| 年化 | 6.78% | **7.85%** |
| 最大回撤 | **-13%** | **-8.97%** |

回撤差了 **4.03 个百分点**（不是 4 倍）。早期版本这里写成“回撤被低估了 4 倍”——**这正是本项目要消灭的那类单位混用错误**，修正于此。

而如果我从来没建这个系统、从来没写那条测试，我会拿着 -13% 去做真实的投资决策，**并且永远不会知道自己错了**。

## 然后我亲手又造了一个 bug

重构到一半，我把调仓逻辑拆成独立函数：

```python
def _rebalance(cash, pos, ...):
    ...
    cash -= cost          # ← 这行什么也没改变
```

`cash` 是 float，Python **按值传递**。这行扣的是一个函数内的副本，调用方的钱一分没少。

结果：**买入从不扣钱，权益凭空膨胀。**

我写的那条测试当场炸了：

```
AssertionError: 23.65 not less than 0.025
```

**23.65%** —— 一个应该只有 1.8% 的现金策略，跑出了 **13 倍**。

如果那条测试不在，这个"优化成果"我就会直接发给你。

## 所以这个仓库长这样

- 每个历史 bug 都有**一条专属回归测试**，注释里写清它曾经造成什么
- CI 在 Python 3.9–3.12 上跑同一套测试
- README、面板顶部、报告 JSON 里都明晃晃写着**这是回测，不是投资建议**

## 修复后的真实结论（说实话版）

初始本金 100 万，佣金 5bp + 滑点 3bp，月度调仓。

**窗口 B（2008-07 ~ 2026-11，4780 个交易日，含金融危机）**

- Steve 配置（静态）：年化 **4.77%**，最大回撤 **-9.96%**，夏普 0.54
- Steve 配置 + 黄金择时：年化 **4.86%**，最大回撤 **-9.39%**，夏普 0.56
- 12 资产等权：年化 7.83%，回撤 -16.34%
- 纯标普500：年化 **10.56%**，回撤 **-47.27%**
- 纯沪深300 ETF：年化 5.47%，回撤 **-52.89%**

**结论就是一句话：这套配置的价值是压回撤，不是提收益。**

跨 18 年含 2008 危机，回撤只有 -9.96%，同期沪深300 是 -52.89%、标普500 是 -47.27%。

代价是**年化少赚 5.7 个百分点**。

如果你要最高收益，这套配置是错的答案。如果你要"18 年不被打爆"，它可能是。

另外两个诚实的坏消息：
- **黄金分档择时基本没用** —— 年化只提升 0.3pp，回撤几乎没改善
- **MA200 趋势风控层完全无效** —— 对 2008 年回撤毫无改善

两个都是我自己提出来、自己加上去的，验证完发现没用，就写进"已知局限"里，而不是藏起来。

## 顺带做了个房产模块

这个项目本来是为回答一个问题写的：**同一笔钱，买房和拿在手里买理财，哪个划算？**

现在面板里有个完整模块：等额本息摊还、租金税费、空置损耗、物业费、买卖税费全部建模，
输出保本租金、保本房价年化、一次性跌幅，外加「房价 × 租金 × 利率」敏感性网格。

以占位假设（60 m²、9 万/m²、月租 6000、首付 35%、3.0%/30 年、房价年化 +2%）算：

- 净租金回报 1.22%，房贷利率 3.0% → **carry −1.78%**
- 3 年后持房比持币少约 **9.6 万**
- 但敏感性网格 75 格里只有 6 格持房占优 → **结论不稳健**

所以正确的说法是：**以这组假设，租房+理财在 3 年尺度上占优，但优势不大、也不稳健。**

⚠️ 关键是这个模块**不接入任何挂牌数据**。挂牌价 ≠ 成交价，贷款和税费要银行预审。
它给的是框架，不是答案。
